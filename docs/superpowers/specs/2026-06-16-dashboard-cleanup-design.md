# 大屏界面清理设计

日期：2026-06-16

## 背景

当前主界面由固定顶部栏、左侧悬浮查询面板、中间图谱、右侧详情栏、图谱顶部指标/导出区和底部分页栏组成。用户希望清理大屏界面中不必要的固定区域，让图谱成为第一视觉层；可折叠的内容都改为可折叠悬浮面板，并且折叠后的入口也可以移动。

## 目标

- 默认以图谱为主，减少固定 UI 占位。
- 所有辅助内容改为可折叠悬浮面板。
- 折叠入口采用左侧竖向停靠形态，但每个入口可独立拖动。
- 折叠入口位置、展开面板位置、展开状态使用 `localStorage` 持久化。
- 移除底部分页 UI，不再提供上一页、下一页、页码、每页数量等界面控件。
- 查询固定加载 200 条数据。

## 非目标

- 不重写查询、密钥、注册、交易等业务 controller。
- 不引入面板缩放能力；首版仅保存位置和折叠状态。
- 不实现自动按性能降级的查询策略。
- 不新增后端接口。

## 整体布局

主界面重组为完整大屏工作台：

- `WorkspaceShell`：全屏容器，负责背景、图谱主区域和悬浮层。
- `NetworkGraph`：占满主要视觉区域，保留图谱交互、工具按钮和图例。
- `FloatingDock`：左侧竖向折叠入口层。每个入口是一个独立可拖动图标。
- `FloatingPanelLayer`：承载展开后的悬浮面板。每个面板都可拖动、折叠，并保存位置。

首次进入且无本地布局记录时，所有面板默认折叠，只显示图谱和 dock 图标。之后进入时从 `localStorage` 恢复各面板的展开状态、折叠入口位置和展开面板位置。

## 面板拆分

### 查询面板

保留：

- API 基址
- 查询模式
- 节点 ID / 公钥
- 循环状态
- 币种
- 加载按钮
- 请求 URL
- 浏览节点
- 密钥保险库
- 添加/导入节点

移除：

- 页码输入
- 每页数量输入

查询行为固定为 `page=0`、`size=200`。

### 详情面板

从右侧固定栏改为悬浮面板。保留当前选中节点/边详情、本地节点操作、交易记录/挂载表单、交易证据和回流信息。未选择对象时显示简短空状态，但默认折叠。

### 循环面板

从详情面板顶部拆出为独立悬浮面板。保留排序控件、循环列表和空状态。

### 指标面板

原图谱顶部 4 个指标拆为独立悬浮面板：

- 总链路
- 成环
- 开放
- 流量

### 导出面板

原 CSV、JSON、复制 curl 拆为独立悬浮面板。无数据时继续禁用对应操作。

### 系统状态面板

原顶部品牌、数据源、节点数、边数、区块高度、待处理消息、中心公钥冻结状态整合为独立状态面板。固定顶部栏移除后，系统状态面板是唯一状态入口。

## 移除内容

- 固定顶部栏。
- 图谱顶部固定指标/导出区域。
- 图谱欢迎说明卡片。
- 固定右侧详情栏。
- 底部分页栏。
- 查询面板中的页码和每页数量字段。

## 布局状态模型

新增 `localStorage` key：`nmsci.dashboard.layout.v1`。

每个面板保存：

```ts
type DashboardPanelLayout = {
  collapsed: boolean
  dockPosition: { x: number; y: number }
  panelPosition: { x: number; y: number }
}
```

首版支持的面板 id：

- `query`
- `details`
- `loops`
- `metrics`
- `export`
- `system`

状态读取规则：

- 读取失败时使用默认布局。
- JSON 结构不符合预期时使用默认布局。
- 缺失的面板字段用默认值补齐。
- 面板位置或 dock 位置超出可视区域时夹回工作区内。

状态写入规则：

- 折叠/展开时写入 `collapsed`。
- dock 拖拽结束时写入 `dockPosition`。
- 展开面板拖拽结束时写入 `panelPosition`。
- 拖拽移动过程中不高频写入 `localStorage`。

## 默认布局

默认 dock 入口靠左竖向排列：

- 查询：`x=16, y=16`
- 详情：`x=16, y=72`
- 循环：`x=16, y=128`
- 指标：`x=16, y=184`
- 导出：`x=16, y=240`
- 系统：`x=16, y=296`

默认展开面板位置：

- 查询：`x=72, y=16`
- 详情：右侧 16px、上方 80px
- 循环：右侧 16px、上方 360px
- 指标：`x=72, y=96`
- 导出：`x=72, y=176`
- 系统：`x=72, y=256`

默认所有面板 `collapsed=true`。

## 组件边界

新增：

- `DashboardWorkspace`：组合图谱、dock、悬浮面板。
- `FloatingPanel`：通用悬浮面板外壳，负责标题、折叠按钮、拖拽句柄。
- `DockIcon`：通用折叠入口，负责图标按钮、拖拽和可访问名称。
- `useDashboardLayout`：管理布局状态、默认值、校验、持久化。

调整：

- `useDraggable` 扩展为支持初始位置、拖拽结束回调和边界夹取。
- `GraphPanel` 去除固定 header，只保留图谱区域。
- `QueryPanel` 去除页码/每页数量，适配悬浮面板容器。
- `InspectorPanel` 去除固定右栏职责，只保留详情内容分发。
- `LoopsPanel` 从 `InspectorPanel` 中移出，由独立面板承载。
- `FooterBar` 不再渲染。

业务 controller 保持现有职责，不把布局状态混入业务数据流。

## 数据流

`App` 继续持有现有 hooks：

- `useNetworkExplorerController`
- `useLocalKeyringController`
- `useRegistrationController`
- `useLocalNodeActions`
- `useNetworkExplorerActions`

`DashboardWorkspace` 接收这些状态和 action，负责把它们分发给各悬浮面板内容。

查询时固定使用：

- `page=0`
- `size=200`

如果接口失败，沿用现有错误展示和 live region，不做自动重试或降级。

## 可访问性

- 每个 dock 入口必须有 `aria-label`。
- 每个悬浮面板必须有标题和折叠按钮。
- 拖拽句柄保留键盘移动能力。
- 展开/折叠状态通过按钮文本或 `aria-expanded` 表达。
- 业务错误、加载状态继续使用现有 live region / alert 规则。

## 测试策略

更新或新增测试覆盖：

- 首次无布局记录时所有面板折叠，只显示 dock 图标。
- 点击 dock 图标可展开/折叠对应面板。
- 折叠入口位置能写入并从 `localStorage` 恢复。
- 展开面板位置能写入并从 `localStorage` 恢复。
- 查询请求固定带 `page=0`、`size=200`。
- 底部分页栏不再渲染。
- 查询、详情、循环、指标、导出、系统状态都能作为面板打开。
- 现有 App 集成测试按新入口调整后继续覆盖查询、密钥、节点操作和交易操作。

提交前验证：

- `npm test`
- `npm run lint`
- `npm run build`

## 风险与缓解

- 风险：大规模布局重组会影响现有测试定位元素。缓解：先加布局回归测试，再调整既有测试入口。
- 风险：多个悬浮面板位置可能遮挡图谱。缓解：默认全部折叠，并夹取到可视区域内。
- 风险：`localStorage` 旧状态损坏导致界面不可用。缓解：解析失败和结构异常时回退默认布局。
- 风险：一次加载 200 条影响接口和图谱性能。缓解：保留错误展示，首版不做自动降级；后续可根据实际性能再调配置。
